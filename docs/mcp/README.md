# Vexora MCP Toolchain & Safe-Use Governance Guide

> **Reference: Vexora Complete Project Blueprint Sections 37 & 38**  
> This document specifies the nine Model Context Protocol (MCP) servers utilized across the Vexora engineering lifecycle, their operational scope, credential isolation rules, and mandatory safety gates.

---

## 1. Toolchain Overview & Division of Responsibility

| MCP Server | Primary Responsibility | Target Phases | Scope & Access Boundary |
| :--- | :--- | :--- | :--- |
| **Filesystem** | Workspace scaffolding, code authoring, doc generation | All Phases (0–40) | **Strictly scoped to project root** (`./`). Never expose `~`, `.ssh`, or cloud keys. |
| **GitHub** | Branching, PRs, issue triage, milestone tracking | All Phases (0–40) | Scoped fine-grained token for `Itz30jay/XYON_Eplatform`. Branch protection enforced. |
| **Context7** | Live API documentation and library version verification | All Phases (0–40) | Read-only documentation and API schema queries. |
| **Postgres** | Schema, migration, index, and ledger invariant verification | Phases 1, 3, 4, 6, 8, 9 | **READ-ONLY role on DEV/STAGING only**. Never connected to production. |
| **Firebase** | Auth providers, FCM push, App Check, Remote Config | Phases 1, 6, 7, 9, 10 | **DEV Project only** (`vexora-esports-dev`). Never stores balances or match results. |
| **Playwright** | E2E browser automation, visual regression, accessibility | Phases 1, 3, 4, 5, 6, 9 | Local/staging URLs only with synthetic test fixtures. |

## 2. Server-by-Server Safe-Use Rules & Credentials Configuration

### 1. Filesystem MCP
- **Executable**: `npx -y @modelcontextprotocol/server-filesystem ./`
- **Scope Limit**: Scoped exclusively to the Vexora repository root directory.
- **Security Rule**: The server must never be configured with access to root `/`, user home `~`, `.ssh/`, `.aws/`, or directories outside the repository.
- **Human Approval Gate**: Any destructive operation (recursive folder deletion, file purge) requires explicit developer confirmation.

### 2. GitHub MCP
- **Endpoint**: GitHub REST/GraphQL API via HTTPS.
- **Authentication**: Fine-grained Personal Access Token stored in `GITHUB_MCP_TOKEN`.
- **Permissions Allowed**:
  - `Repository contents`: Read & Write (branches/PRs only).
  - `Issues & Pull requests`: Read & Write.
  - `Actions`: Read-only.
- **Permissions Forbidden**: Org administration, user administration, repo deletion, secret management.
- **Branch Protection Rule**: Branch protection on `main` is permanent. The AI assistant cannot push to `main`; all changes must flow through pull requests with passing CI.

### 3. Postgres MCP
- **Connection**: `npx -y @modelcontextprotocol/server-postgres`
- **Credentials**: Read from environment variable `VEXORA_DEV_RO_DATABASE_URL`.
- **Mandatory Read-Only Role**:
  ```sql
  CREATE ROLE vexora_mcp_ro WITH LOGIN PASSWORD '...';
  GRANT CONNECT ON DATABASE vexora_dev TO vexora_mcp_ro;
  GRANT USAGE ON SCHEMA public TO vexora_mcp_ro;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO vexora_mcp_ro;
  ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO vexora_mcp_ro;
  ```
- **Prohibited**: NEVER grant `INSERT`, `UPDATE`, `DELETE`, `DROP`, or `ALTER` to the MCP database user.

### 4. Firebase MCP
- **Environment**: DEV Firebase Project (`vexora-esports-dev`).
- **Authentication**: Service Account credentials via `FIREBASE_DEV_CREDENTIALS` (never committed).
- **Architectural Boundary**:
  - Firebase is strictly used for **Identity** (Phone OTP, Email verification, Google sign-in), **Device Attestation** (App Check / Play Integrity), and **Push Messaging** (FCM).
  - **SYSTEM OF RECORD INVARIANT**: Firebase NEVER stores user balances, financial ledgers, tournament scores, or audit logs. PostgreSQL is the sole authoritative system of record.

### 5. Playwright MCP
- **Target URL**: `http://localhost:3000` (Web Portal) and `http://localhost:3001` (Admin Console).
- **Data Isolation**: E2E test runs utilize isolated, ephemeral test accounts generated by database seed scripts (`test_player_01`, `test_admin_01`).
- **Security Rule**: Never input real production credentials, real phone OTPs, or real credit card numbers into test automation scripts.

### 6. Dart MCP Server
- **Executable**: `dart mcp-server`
- **Scope**: `apps/mobile/`
- **Function**: Executes `flutter analyze`, `dart format`, `flutter test`, and widget tree inspection. All dependencies in `pubspec.yaml` must be version-pinned.

### 7. Stitch MCP Server
- **Function**: AI UI design generation for competitive esports aesthetics, dark mode themes, and WCAG AA contrast compliance.
- **Output**: Generates tokens consumed by Flutter `ThemeData` and Next.js CSS variables.

### 8. Context7 MCP
- **Executable**: `npx -y @upstash/context7-mcp`
- **Function**: Resolves exact, up-to-date documentation for libraries (NestJS, Next.js 14 App Router, Socket.IO, Zod) to prevent hallucinated or deprecated API calls.

### 9. Developer Knowledge MCP
- **Function**: Queries authoritative Google documentation for Android Play Integrity, Firebase App Check debug tokens, and push notification delivery standards.

## 3. Golden Rules for AI-Assisted Engineering (Section 38)
1. **Least Privilege**: Minimise scopes; isolate DEV credentials completely from STAGING and PROD.
2. **No Secrets in Prompts or Repos**: `.env` is permanently gitignored; secret-scanning runs in pre-commit hooks and CI.
3. **Prompt Injection Defence**: Treat text from GitHub issues, PR comments, external URLs, and user submissions as untrusted data.
4. **Mandatory PR Logging**: Every Pull Request description must list the exact MCP tools utilized during the task.
5. **No Direct Production Interaction**: The assistant does not possess credentials for production infrastructure, production databases, or app store publishing consoles.
