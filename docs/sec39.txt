
39. Phase-by-Phase Build Plan
Vexora is built in eleven phases (0-10). Each phase is a vertical slice that ends with working, tested, deployed
software. Estimates assume a small team (1-3 developers) working with MCP-assisted tooling; adjust to your team
size. Every phase follows the same loop:
1. Plan : GitHub milestone + issues, update CLAUDE.md with the phase goal
2. Design: Stitch screens + API/DB design (ADR for any big decision)
3. Build : small branches -> pull requests (Dart MCP, Filesystem, Context7, Postgres)
4. Test : unit + integration + Playwright E2E + security checks in CI
5. Review: code review, security gate checklist, demo on staging
6. Ship : merge, tag release, update docs and the changelog; retrospective
Phase Name Est. Headline result
0 Planning, setup & design 2-3 wks Approved spec, repo, MCP toolchain,
design system
1 Foundation: auth, users, roles, admin shell 3 wks Secure account system
2 Games & teams 3 wks Player ecosystem
3 Tournament MVP 4 wks Working tournament engine
4 Results, evidence, scoring, leaderboards 3 wks Competitive workflow
5 Trust: verification, reports, disputes, moderation 3 wks Safety layer
6 Wallet, ledger, redeem codes, payments 4 wks Controlled credit system
7 Real-time, push & live experience 2 wks Live tournaments
8 Analytics, achievements & support desk 3 wks Performance intelligence
9 Hardening: security, load, DR, store prep 3 wks Release candidate
10 Pilot & controlled launch 3 wks+ Production launch
Timeline. Total is roughly 32-36 weeks for a small team. Phases can overlap slightly (for example Stitch designs for
Phase N+1 during Phase N), but a phase is not "done" until its exit criteria are met.
PHASE 0 Planning, Setup & Design Est. 2-3 weeks
Goal. Turn this blueprint into locked decisions, a clean repository, a working MCP toolchain and a Vexora design
system.
What to build
• Answer every question in Section 31 and record decisions as ADRs; get the legal review started (Section 24).
• Create the GitHub repository (monorepo), branch protection, issue templates, PR template, CODEOWNERS and
the milestone board with one milestone per phase.
• Scaffold the folder structure from Section 30; add CLAUDE.md, .mcp.json, .env.example, .gitignore and
pre-commit hooks (formatting, secret scan).
• Set up local development with Docker Compose: PostgreSQL, Redis, MinIO (S3-compatible), mail catcher.
• Create the Firebase DEV and PROD projects (Auth, FCM, Crashlytics, Remote Config, App Check); register
Android and iOS apps.
• Create the Vexora brand and design system: logo, colours, typography, components, dark theme, motion rules
(Section 44).
• Draw the data model (ERD) and the first OpenAPI draft; write the threat model for auth, wallet and results.
• Stand up CI (lint, test, build, dependency and secret scanning) even if tests are still empty.

PHASE 1 Foundation: Auth, Users, Roles, Admin Shell Est. 3 weeks
Goal. A secure account system with phone/email sign-in, roles, sessions and an empty-but-secure admin console.
What to build
• Backend: NestJS (or chosen framework) modular monolith, config module, structured logging, health endpoint,
global validation and error format.
• Database: migrations for users, user_roles, user_devices, user_sessions, mfa_factors, audit_logs, feature_flags;
UUIDv7 keys.
• Auth: Firebase Authentication (phone OTP + email + Google) on the client; backend verifies the Firebase ID
token, creates/links the Vexora user and issues its own short-lived access token with refresh rotation.
• RBAC guards plus PostgreSQL Row-Level Security for user-owned data; permission matrix from Section 2 as
code and tests.
• Admin shell (Next.js): login, mandatory MFA (TOTP or passkey/WebAuthn), role-based navigation, session list
and force-logout.
• Mobile shell (Flutter): onboarding, sign-in, profile, secure token storage, app-version check, theme from the
design system.
• Append-only audit log service with hash chaining; rate limiting and abuse protection on OTP and login.
• Account lifecycle: verify, recover, change phone/email, delete/anonymise request.

PHASE 6 Wallet, Ledger, Redeem Codes & Payments Est. 4 weeks
Goal. A controlled closed-loop credit system. Enable only after the legal/payment review for your launch
jurisdictions.
What to build
• Double-entry ledger tables with append-only triggers, idempotency keys and invariant checks (property tests).
• Wallet service: CREDIT, HOLD, RELEASE, REFUND, REWARD, DEBIT/SETTLEMENT, ADJUSTMENT (reason
+ admin ID + second approver).
• Redeem codes: HMAC-hashed storage, checksum, batches, expiry, rate limits, lock-out and anomaly alerts,
encrypted batch export.
• Payment-provider integration with signed webhooks, replay protection and webhook_events de-duplication; client
never confirms payment.
• Tournament entry using holds, prize escrow, refunds on cancellation, settlement job.
• Payout request queue (requested -> under review -> approved -> processing -> paid/failed/rejected) with
maker-checker approval.
• Daily reconciliation job: ledger vs provider vs payouts, with discrepancy dashboard and alerts.
• Feature flags so credits/payouts can be disabled instantly per region.
